# PLAN — Dev Schema Sync (`db.Sync`) + `ActionAddColumn` (orm core)

> Master orchestrator for **dev-time schema sync** in `tinywasm/orm`: a runtime
> `db.Sync(models...)` that reconciles the database to match the models **additively and
> idempotently**, by emitting agnostic `Action`s through the injected `Compiler`/`Executor`.
> Paired with hot-codegen wiring in `tinywasm/app`, a developer changes a `model.go` field and
> it appears in the dev DB within one rebuild cycle — **no migration files**.
>
> **The model is the schema; git is the history.** Versioned, file-based migrations for
> production deploys are **deferred** (see §8).

**Scope of THIS plan = `tinywasm/orm` only.** The agnostic contract is `ActionAddColumn`. Each DB
engine implements that command in its **own** self-contained plan (engines already handle
`ActionCreateTable`): `tinywasm/postgres/docs/PLAN.md` and `tinywasm/sqlt/docs/PLAN.md`.
Cross-module order in §4.0.

Related: [ARQUITECTURE.md](ARQUITECTURE.md) · [IMPROVE.md](IMPROVE.md) §3

---

## 1. Development Rules (constraints copied for execution context)

- **One build profile per package.** The root `orm` package is **purely isomorphic** (runtime;
  the generated `*_orm.go` imports it from WASM) — **zero build tags**. The codegen tools live in
  a separate backend-only subpackage **`orm/ormc`** (package `ormc`). A consumer that needs only
  codegen (e.g. `tinywasm/app`) imports `orm/ormc` and never drags in the runtime DB API. (Step 1.)
- **Runtime applies through DI.** `db.Sync` uses the **injected** `Compiler` + `Executor` (same
  pipeline as `Create`/`Update`/`CreateTable`). No new connection, no driver import in `orm`.
  Compiles for backend and WASM; keep it `reflect`-free and minimal.
- **Engine-agnostic — `db.Sync` emits only `Action`s, never per-dialect SQL.** The SQL string and
  its execution are produced **inside each engine adapter** (postgres, sqlt), each documented in
  its own `docs/PLAN.md`. `orm` defines the `ActionAddColumn`, `ActionRenameColumn`, and `ActionDropColumn`
  contracts and carries metadata on `Query`.
- **Additive, Rename-Supporting, and Safe-Deletion.** v1 reconciles by adding missing elements,
  renaming columns with explicit hints (`db:"old_name=X"`), and deleting columns only if they do not
  contain data. Re-running is a no-op. Full destructive/altering migrations are deploy-only (§8).
- **No files, no global state.** `db.Sync` takes the model list as a **parameter** (DI). No
  `migrations/` folder, no `// ormc:baseline`, no git diffing, no `schema_migrations` table.
- **Zero reflection.** Schema is `[]fmt.Field`, surfaced via `fmt.Fielder.Schema()`.
- **No `time.Time`.** Unchanged; stated for context.
- **Dev-oriented.** `db.Sync` runs in **DevMode** (the server applies it on startup). Safe to leave
  callable in prod, but the prod evolution story is the deferred versioned plan.

## 2. Problem

During development the schema changes constantly (add a model, add a field). Today nothing
propagates that to the database: `db.CreateTable` only creates a brand-new table and there is
**no `ActionAddColumn`** anywhere in the agnostic pipeline. The developer must drop/recreate by
hand (losing data) or hand-write dialect SQL.

What's wanted: **maximum dev dynamism** — change a model, the DB reflects it immediately — with
**maximum simplicity**: no proliferation of migration files (git already tracks the model's
history). A declarative *sync* from the models to the DB delivers exactly this.

> Rejected: per-save versioned migration files (dozens of throwaway files; git already records
> history). See §8 for the deferred deploy-time versioned design.

---

### 3.1 `db.Sync` — declarative, introspective, agnostic sync

```go
// Sync reconciles the database to match the given models.
// Emits CreateTable, AddColumn, RenameColumn, and DropColumn Actions;
// the engine adapter compiles and executes the dialect SQL.
func (db *DB) Sync(models ...fmt.Model) error
```

`db.Sync` utilizes an optional `TableIntrospector` interface cast on the injected `Executor` to query DB-state:
```go
type TableIntrospector interface {
    TableColumns(table string) ([]string, error)
}
```

Per model, in order:
1. **Create Table:** Emit `ActionCreateTable` (engine handles `IF NOT EXISTS`).
2. **Retrieve Columns:** If the `Executor` satisfies `TableIntrospector`, query the existing columns for the table. If not supported, fallback to additive-only sync with log-and-continue on duplicate column errors.
3. **Reconcile fields (Adds & Renames):**
   - If the model implements `RenameProvider` (generated by `ormc` when `db:"old_name=X"` tags are present):
     ```go
     type RenameProvider interface {
         OldNames() map[string]string
     }
     ```
   - For each field in `Schema()`:
     - If the column exists in the database, skip.
     - If the column does not exist:
       - Check if `RenameProvider` maps this new column name to an `old_name` that does exist in the database.
       - If so, emit `ActionRenameColumn` (with old name and new field metadata).
       - Otherwise, emit `ActionAddColumn`.
4. **Reconcile deleted fields (Safe Drops):**
   - For each column present in the DB table but missing from the model's `Schema()` (and not renamed):
     - Execute a standard SQL query: `SELECT 1 FROM <table> WHERE <col> IS NOT NULL LIMIT 1` (or engine-equivalent).
     - If no rows return, emit `ActionDropColumn`.
     - If rows are returned (column contains data), skip dropping and log a warning: `[orm] WARNING: Column '<col>' in table '<table>' contains data and will not be dropped.`

`db.Sync` stays **fully agnostic** — it only emits `Action`s. The dialect SQL is produced **inside each engine adapter** (postgres, sqlt). The models' `Schema()` is the single source of truth; **git** is the history.

### 3.2 Why declarative sync, not versioned files (for dev)

- **Simplicity / dynamism.** The model *is* the desired state; `db.Sync` makes the DB match it.
  No baseline, no diff engine, no sequence numbers, no folder to curate.
- **Git is the history.** The evolution of `model.go` (+ generated `model_orm.go`) is already
  versioned; a `migrations/` folder would duplicate that.
- **Idempotent = safe in the hot loop.** The server calls `db.Sync` on every restart with no
  accumulation.
- **Agnostic.** Built on `Action`s; Postgres and SQLite both work from the same call, each adapter
  translating per its own plan.

### 3.3 The build/runtime split

`orm/ormc` (build-time, backend-only subpackage, no DB) **generates `*_orm.go`** so `Schema()`
reflects the current model. `db.Sync` (runtime, injected `Compiler`+`Executor`) **applies** it.
**`ormc.Generator` is the watch handler** (Step 4 adds the file-event methods); `tinywasm/app`
only **wires** it into its file watcher and triggers the rebuild/restart — no handler logic of its
own.

### 3.4 Where models + the call live (config seam)

- **The user's server owns the DB connection and the `db.Sync` call.** In DevMode it calls
  `db.Sync(models...)` on startup (after constructing `*orm.DB`). `tinywasm/app` does **not** open
  the user's DB — it only regenerates code and restarts the server.
- **Models are engine-blind.** A velty_module never imports `postgres`/`sqlite`/`indexdb`; the host
  composes the model list for `db.Sync` (mirrors the `modules.Init(db)` DI seam).
- **Backend only.** `db.Sync` runs on the server (Postgres). The WASM/IndexedDB frontend manages
  its object stores via its own `onupgradeneeded` versioning — out of scope.

### 3.5 Engine contract (separate, self-contained plans)

`orm` defines `ActionAddColumn`, `ActionRenameColumn`, and `ActionDropColumn`. **Each engine implements the commands itself**, in
its own repo's `docs/PLAN.md`:
- **postgres** →
  - `case ActionAddColumn`: emits `ALTER TABLE … ADD COLUMN IF NOT EXISTS …`.
  - `case ActionRenameColumn`: emits `ALTER TABLE … RENAME COLUMN old TO new`.
  - `case ActionDropColumn`: emits `ALTER TABLE … DROP COLUMN IF EXISTS …`.
- **sqlt (SQLite)** →
  - `case ActionAddColumn`: emits `ALTER TABLE … ADD COLUMN …`.
  - `case ActionRenameColumn`: emits `ALTER TABLE … RENAME COLUMN old TO new`.
  - `case ActionDropColumn`: SQLite doesn't support dropping columns directly in older versions, but standard newer SQLite supports `ALTER TABLE … DROP COLUMN …`. Adapt to emit `DROP COLUMN` if newer SQLite is targeted, or document limitations.
- **indexdb** → **not needed for v1** (frontend never calls `db.Sync`; its compiler `default`
  already rejects unhandled actions). No plan required now.

This keeps each module self-contained for codejob: orm publishes the contract; each engine adopts
it independently.

## 4. Implementation Steps

### 4.0 Cross-module execution & publish order (read first)

This feature spans separate Go modules (each its own `go.mod`, pinned to a published `orm`):
1. **orm** — Steps 1–5 below → `gopush` a new `orm` version `vX`.
2. **postgres** — bump `orm` to `vX`, execute `tinywasm/postgres/docs/PLAN.md` → `gopush`.
3. **sqlt** — bump `orm` to `vX`, execute `tinywasm/sqlt/docs/PLAN.md` → `gopush`.
4. **app** — bump `orm` to `vX`, wire `ormc.New()` into the watcher (app's own plan).

Steps 2–4 cannot compile against `ActionAddColumn` until step 1 is published.

### Step 1 — Restructure: move codegen tools into the `orm/ormc` subpackage
**Files:** the five `ormc*.go` files → new `ormc/` dir; [cmd/ormc/main.go](../cmd/ormc/main.go)

Clean, cycle-free (verified): the codegen files are the only `//go:build !wasm` files; they
reference runtime types **only inside generated string literals** (`"orm.QB"`, `"orm.DB"`), never
as Go imports; no runtime file references any codegen type.

- Move `ormc.go`, `ormc_handler.go`, `ormc_generate.go`, `ormc_relations.go`, `ormc_tags.go` into
  `orm/ormc/`, change `package orm` → `package ormc`. Suggested renames (drop the `ormc_` prefix):
  `generator.go`, `handler.go`, `generate.go`, `relations.go`, `tags.go`.
- **Drop the `//go:build !wasm` tags** from the moved files — the subpackage is isolated; its
  stdlib deps (`os/exec`, `go/ast`) give a clear compile error if imported from WASM.
- **Rename the type** `Ormc` → `Generator`; constructor `NewOrmc()` → `New()` (`ormc.New()
  *ormc.Generator`).
- Update [cmd/ormc/main.go](../cmd/ormc/main.go): import `github.com/tinywasm/orm/ormc`, call
  `ormc.New()`.
- Root `orm` is now **tag-free, purely isomorphic**. Generated `*_orm.go` still imports
  `github.com/tinywasm/orm` (runtime) — unchanged. Downstream callers of `orm.NewOrmc()` (the
  `form-codegen` skill, item-catalog tooling) migrate to `ormc.New()`.

### Step 2 — Core DDL contract: Add, Rename, and Drop Actions (runtime, root package)
**Files:** [query.go](../query.go)

- Add `ActionAddColumn`, `ActionRenameColumn`, and `ActionDropColumn` to the `Action` enum (`query.go:6-15`), appended after `ActionCreateDatabase` to preserve existing iota values.
- Carry the field and metadata on `Query`:
  ```go
  type Query struct {
      ...
      Column  *fmt.Field // set for ActionAddColumn and ActionRenameColumn (target field schema)
      OldName string     // set for ActionRenameColumn (original column name to rename from)
  }
  ```
- The engines implement compilation/execution routines for these actions (postgres/sqlt repos).

### Step 3 — `db.Sync` with Introspection, Renames, and Safe Deletes (runtime, DI, isomorphic)
**Files:** new [sync.go](../sync.go) (no build tag — isomorphic, root package), [errors.go](../errors.go)

Define the isomorphic interfaces in `sync.go`:
```go
// RenameProvider is implemented by generated models when db:"old_name=X" tags are present.
type RenameProvider interface {
    OldNames() map[string]string
}

// TableIntrospector is optionally implemented by the injected Executor to retrieve column names.
type TableIntrospector interface {
    TableColumns(table string) ([]string, error)
}
```

Algorithm in `func (db *DB) Sync(models ...fmt.Model) error`:
- Wrap each model's sync execution in `db.Tx` when `TxExecutor` is available.
- For each model:
  1. Emit `ActionCreateTable` (idempotent CREATE TABLE IF NOT EXISTS).
  2. Cast `db.exec` (Executor) to `TableIntrospector`.
  3. If not supported, fallback to purely additive loop: emit `ActionAddColumn` for all fields, catching duplicates via log-and-continue.
  4. If supported, call `TableColumns(tableName)` to retrieve `existingCols`.
  5. Check if model implements `RenameProvider` to get the `oldNames` map.
  6. **Reconcile Adds & Renames:**
     - For each `field` in model `Schema()`:
       - If its column name is in `existingCols`, skip.
       - If not in `existingCols`:
         - If `oldNames[field.Name]` exists in `existingCols`, emit `ActionRenameColumn` (setting `Query.Column = &field` and `Query.OldName = oldNames[field.Name]`).
         - Otherwise, emit `ActionAddColumn` (setting `Query.Column = &field`).
  7. **Reconcile Safe Drops:**
     - Identify DB columns in `existingCols` that are not present in Go struct `Schema()` and were not renamed.
     - For each obsolete column:
       - Run check: `SELECT 1 FROM <table> WHERE <col> IS NOT NULL LIMIT 1`.
       - If query returns no rows, emit `ActionDropColumn` (setting `Query.Table = tableName` and `Query.Columns = []string{col}`).
       - If query returns rows (has data), skip drop and log warning: `[orm] WARNING: Column '<col>' in table '<table>' contains data and will not be dropped.`
- Surface a sentinel `ErrSyncFailed` in `errors.go` for fatal failures (e.g. `CreateTable` error).
- Re-running `db.Sync` is completely idempotent. No DB changes are written on second run.

### Step 4 — Make `ormc.Generator` a watch-ready file-event handler
**Files:** new `ormc/watch.go` (package `ormc`, no build tag), `ormc/handler.go`, `ormc/generator.go`

The codegen **handler already exists** (`ormc.Generator` with `Run()`/`SetRootDir`/`SetLog`, after
Step 1). Add the **file-event contract** so a watcher (`tinywasm/app`'s `devwatch`) can drive it
directly. **`tinywasm/app` adds no handler of its own — it only wires `ormc.New()` into its watcher
list.** Structural — Go satisfies the interface by signature, so **`orm/ormc` does not import
`devwatch`**:
- `NewFileEvent(fileName, extension, filePath, event string) error` — if `fileName` is `model.go`
  or `models.go`, call `Run()`; otherwise return `nil`.
- `SupportedExtensions() []string` → `[]string{".go"}`.
- `UnobservedFiles() []string` → `nil`.
- `MainInputFileRelativePath() string` → `""`.

Plus a **tidy-skip**: add `skipTidy bool` + `SetSkipTidy(bool)`; when set, `Run()` skips Pass 5
(`go mod tidy`). CLI default (`ormc` binary) unchanged.

## 5. Edge Cases (orm scope)

- **Column renamed in the model** → Reconciled using `db:"old_name=X"` tags. Emits `ActionRenameColumn` (`ALTER TABLE ... RENAME COLUMN ...`). If the old column does not exist in the database, fallback to `ActionAddColumn`.
- **Column removed in the model** → If the column contains no data (all values are NULL/default), it is dropped using `ActionDropColumn` (`ALTER TABLE ... DROP COLUMN ...`). If it contains data, the column is preserved and a warning is logged.
- **Column retyped in the model** → Currently ignored (preserved as-is in the DB). Full retyping requires SQLite table rebuilding, which is deferred to versioned migrations (§8).
- **`TableIntrospector` not supported by engine** → Fallback to purely additive mode (duplicate column warnings caught by log-and-continue).
- **`AddColumn` error from the engine** → logged as a warning, sync continues (§3.1).
- **`// orm:no_db` struct** → no DB layer; not passed to `db.Sync`.
- **Re-running `db.Sync`** → idempotent (no diff state needed).
- **Empty model list** → no-op.
- **`CreateTable` fatal error** → returns `ErrSyncFailed` (table creation is not best-effort).
- **NOT NULL / PK / unique on an added column** → an **engine** concern.

## 6. Test Strategy (orm scope)

`gotest` in `tinywasm/orm/tests/`. Engine SQL is tested in each engine's repo (its own plan).

| # | Case | Assert |
|---|------|--------|
| S1 | `db.Sync` new model | a `CreateTable` Action is issued (MockCompiler/Executor) |
| S2 | `db.Sync` model with N fields | N `AddColumn` Actions issued, each carrying the right `Query.Column` |
| S3 | `db.Sync` where one `AddColumn` errors | error **logged**, loop continues, remaining columns attempted |
| S4 | `db.Sync` where `CreateTable` errors | returns `ErrSyncFailed` |
| S5 | `db.Sync` empty model list | no-op, nil error |
| S6 | `db.Sync` inside `Tx` when `TxExecutor` present | ops run within a transaction |
| S7 | `ormc.Generator.SetSkipTidy(true)` then codegen | `*_orm.go` regenerated; `go mod tidy` **not** run |
| S8 | `ormc.Generator.NewFileEvent("model.go", …)` | `Run()` invoked |
| S9 | `ormc.Generator.NewFileEvent("handler.go", …)` | ignored — no regen, returns nil |
| S10 | `*ormc.Generator` satisfies `FilesEventHandlers` | the 4 methods present (compile-time assert) |
| S11 | `db.Sync` with rename provider | `ActionRenameColumn` is issued with appropriate `OldName` and `Column` |
| S12 | `db.Sync` with removed field (no data) | `ActionDropColumn` is issued for the obsolete column |
| S13 | `db.Sync` with removed field (has data) | No action issued for the column; warning is logged |

Use `MockExecutor`/`MockCompiler` so S1–S6 and S11–S13 assert the issued `Action`s/plans without a real DB.

## 7. Validation (end-to-end, the hot loop)

After orm + the engine plans + app wiring land:
1. Add a field to a `model.go` struct and save.
2. app's `ormc.Generator` regenerates `*_orm.go` (Schema() now has the field).
3. app recompiles + restarts the user's server.
4. The server (DevMode) calls `db.Sync(models...)` → the engine issues `ADD COLUMN` → Postgres gets
   the new column.
5. Re-save with no schema change → `db.Sync` is a no-op (log-and-continue absorbs the duplicate).

## 8. Deferred — Versioned migrations for production deploy (future plan)

Out of scope here (deploy deferred: *"una vez conforme, simplemente despliega — no relevante en
este feat aún"*). A future plan will cover the versioned, file-based path `db.Sync` omits:

- Build-time diffing of models against a committed baseline → ordered migration files.
- Tracking applied migrations (`schema_migrations`) + a versioned apply.
- Destructive/altering ops (DROP/rename/type-change) with SQLite's table-rebuild.
- `Down`/rollback, data migrations, squashing.
- An `Introspector` interface for precise (non-log-and-continue) idempotency, if needed.
